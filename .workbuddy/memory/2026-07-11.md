## 镜像 load 交付的硬限制（重要）
- 用户要求 `docker load -i` 形式，但本机 Mac 是 arm64，Docker 默认构建 arm64 镜像；服务器实测为 x64（lscpu 显示 x86_64 / AMD EPYC）。
- 构建 x64 镜像需拉 amd64 基础镜像，但本机连不上 Docker Hub（之前拉 node:20-slim 报 token EOF），本地无 amd64 基础镜像 → 本机无法产出可 load 的 x64 镜像。
- 故改为「源码包 + 服务器 build」方案。重新打包 /tmp/pm-project-docker.tar.gz（328K，含修复版 Dockerfile）。
- Dockerfile 修复（build 失败根因）：① pnpm 版本切换签名超时 → 锁死 pnpm@9.0.0 精确版（与 package.json packageManager 一致）；② ECONNRESET → 改用 registry.npmmirror.com 国内源 + --network-concurrency=4 --fetch-retries=5；③ 单阶段构建只装一次依赖，结尾 `pnpm prune --prod`。
- 待确认：目标服务器能否访问 Docker Hub（docker pull）？能→服务器直接 build；不能→需先从能联网处 save 基础镜像 node:22-bookworm 传过去 load 再 build。

## 修正：本机其实能连 Docker Hub + 最终镜像交付
- **推翻上面"本机连不上 Docker Hub"的结论**：那次失败是 docker 命令在**沙箱内**被网络隔离所致（拉 node:20-slim 报 token EOF）。以 `dangerouslyDisableSandbox: true` 在沙箱外执行后，Docker Hub 实际**可达**（build 能正常拉 amd64 基础镜像）。用户也确认本地能连。
- 因此 `docker load -i` 方案可行：本机 arm64 Mac 用 `docker build --platform linux/amd64 -t pm-project:deploy .` 强制构建出 **x64 镜像**（经 QEMU 模拟，build 较慢但成功，BUILD_EXIT=0）。
- 镜像确认：架构 **amd64**、入口 `sh -c node dist/server.js`、NODE_OPTIONS=--openssl-legacy-provider、PORT=5000、size≈605MB。
- 导出：`docker save -o /tmp/pm-project-deploy.tar pm-project:deploy` → 交付物即此 tar，服务器 `docker load -i /tmp/pm-project-deploy.tar` 即得到 pm-project:deploy 镜像。
- 服务器启动注意：镜像为 load 进来（非 build），docker-compose.yml 需把 `build:` 改为 `image: pm-project:deploy`；或用 `docker run -d -p 5000:5000 --env-file .env --name pm-project pm-project:deploy`。运行时必须经 -e/--env-file 传入 DB_HOST/DB_PASSWORD/JWT_SECRET（镜像不含 .env，且 .dockerignore 已排除 .env*）。
- **已实际修改 docker-compose.yml**：删除 `build:` 段、`image: pm-project:latest` → `image: pm-project:deploy`，`docker compose config` 校验通过（COMPOSE_CONFIG_OK）。服务器只需该 compose + .env + 已 load 的镜像即可 `docker compose up -d`。
